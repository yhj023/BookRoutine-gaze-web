This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev`: dev server. Routes (`src/App.tsx`, no router library): `/` intro for visitors (try steps, then pipeline with SVG illustrations from `src/components/IntroArt.tsx` that use no real face or eye images, then features, privacy at the bottom), `/tech` technical explanation, shown as slides (`src/components/Slides.tsx`: tabs, prev/next, ← → keys, touch swipe, synced to `#id`; `SECTIONS` must match the `<section>` children in order) (model, eye crop, calibration, judging rules, reading-scene math; numbers are read from the `*_POLICY` objects so the page stays in sync), `/try` (a [시작] button enters fullscreen and mounts `TryExperience`; leaving fullscreen unmounts it, which stops the camera and clears calibration), and `/collect` (URL only, not in `TopNav`). `TopNav` hides while fullscreen. `predev`/`prebuild` run `scripts/copy-assets.mjs`, which copies the MediaPipe WASM and `reference/face_landmarker.task` into `public/` (gitignored), so nothing is fetched from a CDN.
- Deploy: EC2 nginx on a subdomain (the code uses root-absolute paths such as `/models/...`, so a subpath would need code changes). Steps are in `deploy/DEPLOY.md` (Gabia DNS A record, scp + rsync to `/var/www/gaze-web`, certbot for https), and the server block is `deploy/nginx-gaze.conf` (SPA fallback, `application/wasm`, cache headers, gzip). `/collect` stays in the production build.
- `npm run build`. `npm run typecheck` runs `tsc --noEmit` (app code, no Node types) plus `tsc --noEmit -p tsconfig.test.json` (tests and `testUtils.ts`, with `@types/node`). A bare `npx tsc --noEmit` skips the test files.
- `npm test` (vitest). Single file: `npx vitest run src/gaze/eyeCrop.test.ts`. Filter by name: `-t "<name>"`.
- Python comparison (system Python with mediapipe/opencv/numpy, always run with `python -I`):
  - `npm run compare:ops`: OpenCV reference outputs for warpAffine/resize/getRotationMatrix2D → `data/compare/ops/`, checked by `src/gaze/eyeCrop.ops.test.ts`.
  - `npm run compare:py`: runs `reference/eye_extractor.py` on `data/compare/*.png` (saved with the "사진 저장" button on `/try`) → `data/compare/out/`, checked by `src/gaze/eyeCrop.compare.test.ts`.
  - `npm run compare:gaze`: runs `gaze.tflite` (Python `ai-edge-litert`) on those Python crops → `<stem>.py.gaze.json`. Then press "비교 실행" on `/try` (dev only; reads `data/compare/out` through the `/__compare` middleware in `vite.config.ts`, runs WebGPU and wasm), move the downloaded `gaze-compare.json` into `data/compare/`, and `src/gaze/gaze.compare.test.ts` checks it (|Δ| < 0.01 cm).
- `npm run analyze:calib` (vite-node): reads `data/calib/*.json` (the "보정 데이터 저장" button on the calibration result screen, numbers only) and prints, per point, how much error comes from sample shake versus systematic offset. It reuses `src/gaze/gazeCalibration.ts`. The model's own training error is about 4.5 cm (user, 2026-11-10), so calibration errors near 5 cm are close to the model's limit.
  - Comparison tests skip themselves when their data folder is missing. `data/` is gitignored.
- `/collect` (dev data collection for fine-tuning, Chrome/Edge only): enter participant ID and the screen size as diagonal inches only (cm computed from the `screen.width/height` aspect, no ruler; the button lists what is still missing), then pick a folder via `showDirectoryPicker`. It shows 4×6 cell-center dots, 2 laps, shuffled per lap, 2 s each, and saves at 0.6 s + every 0.25 s. Frames with no face or `eyeBlink` > 0.5 are skipped. It writes `<id>_<local time>/left|right/000001.png` (64×64 crops from `extractEyes`, never the full face), `labels.csv` (same columns and CRLF as `reference/prepare_data.py`, gaze in screen cm from the top-left), and `meta.json`. Logic and numbers are in `src/collect/collectPlan.ts` (`COLLECT_POLICY`). Inside the repo, save to `collected/` (gitignored).

## Gaze model (`src/gaze/gazeModel.ts`, LiteRT.js)

`reference/gaze.tflite` (PyTorch MobileNetV3 export) takes `serving_default_args_0` = image-left eye (`extractEyes().leftEye`, 33/133) and `serving_default_args_1` = image-right eye, each `[1,64,64,3]` float32 **RGB 0–255** (the /255 and normalization are inside the model). The output is `[1,2]` gaze (x, y) in cm, camera-relative and uncalibrated. Inputs are matched by name, not position. WASM and model are served from `public/litert/wasm` and `public/models/`. The app runs it on **wasm (CPU)**, which matches Python exactly (0 diff). WebGPU defaults to fp16 and was off by 0.14–0.74 cm on the same crops, so it only appears in the dev comparison panel. `gpuOptions: {precision: 'fp32'}` exists but is untested.

## Eye crop (`src/gaze/eyeCrop.ts`)

A line-by-line port of `EyeExtractor.process`. It reimplements OpenCV's own arithmetic (not canvas drawImage) so the crops match what the model was trained on. These details were verified against OpenCV 5.0.0:
- `getRotationMatrix2D` takes the center as float32.
- `warpAffine` uses OpenCV 5's float32 path (inverse matrix → float32, FMA-style lerp, round half to even). Expect ≤1 diff on fewer than 0.1% of values (true .5 ties).
- `resize` INTER_LINEAR uses 11-bit fixed-point weights and the SIMD vertical formula. x positions are clamped at the edges, y positions are not (only the row index is clipped). An exact 2× downscale switches to INTER_AREA. This matches exactly.
- numpy float32 steps in the Python code are mirrored with `Math.fround`.
If OpenCV is upgraded, rerun `compare:ops` before trusting the crops.

## Reference material (`reference/`)

Source files and model assets copied from the earlier (mobile) version of the BookRoutine gaze/focus feature. Port from them; they are not wired into the build.

### What the reference code does

It is a webcam-based "is the reader focused?" pipeline for an e-book reader. Comments and UI strings are in Korean; keep new user-facing strings in Korean too.

1. **Face landmarks**: `face_landmarker.task` is the MediaPipe Face Landmarker model (478 landmarks, iris included, Tasks API, not the legacy `face_mesh`).
2. **Eye preprocessing**: `eye_extractor.py` (Python/OpenCV, used on the training side) rotates the face so the eye-corner line is horizontal, scales it to a fixed inter-eye distance (35% of a 224px face), then crops square left/right eye patches (64px, box = eyelid-ring extent × 1.8). The normalization uses eye *corners* (33/133, 263/362), never the iris, because the iris moves with gaze. Any in-browser preprocessing that feeds `gaze.tflite` has to reproduce this exactly, or the model's inputs won't match what it was trained on.
3. **Gaze model**: `gaze.tflite` is a CNN that outputs a gaze point in **cm** (it was trained on laptop-screen data).
4. **Posture check** (`postureCheck.ts`): runs before calibration and checks that conditions resemble the training data: face width 28–70% of frame, yaw ±15°, pitch ±20°, both eyes open ≥ 0.4, eye brightness 50–220.
5. **Calibration** (`gazeCalibration.ts`): 5 targets (center plus 4 corners at a 15% inset) and a 3 s center fixation. It fits a least-squares affine map from model cm to screen coordinates, scores accuracy with leave-one-out error, and measures noise from the fixation. If quality is `poor`, `map` is `null` and judging falls back to head pose only.
6. **Focus judging** (`focusJudge.ts`, class `FocusJudge`): a stateful per-sample classifier that returns `focused | unfocused | away`, plus a `detail` (`staring | skimming | offscreen | head | eyes-closed`). The order of checks matters and is documented in the file header. It has two baseline modes:
   - calibrated (`setCalibration`): gaze is mapped to the screen and judged on-screen vs off-screen, plus a "staring" check (gaze barely moving for 10 s with no scroll);
   - auto: a 5 s self-baseline of head pose and raw gaze, used when calibration is skipped.
   The result goes through majority-vote smoothing (window 3), and the baseline slowly adapts while the reader is focused. Scroll events come in through `notifyScroll(t, y)` and feed the skimming detector (faster than 45 dp/s over 30 s).

All thresholds live in the `*_POLICY` constant objects at the top of each TS file. Tune them there; don't add magic numbers inline. The TS modules are written as pure logic (no React/DOM) so they can be unit-tested. Keep that separation when porting.

### Porting notes

- The TS files import modules that aren't in this repo: `FocusState` from `../types/ebook`, and `GazeSample` from `./useGazeSampler` (a hook producing `timestamp, faceDetected, faceWidthRatio, yaw, pitch, leftEyeOpen, rightEyeOpen, eyeBrightness, gaze, error`). These have to be recreated for the web.
- Screen units in the reference are Android **dp** (`CM_PER_DP = 2.54/160`), and policy values such as `SKIM_MAX_DP_PER_SEC` and `STARE_MIN_SPREAD_DP` assume dp. On the web, decide explicitly how CSS px map to these values instead of swapping the units silently.
- **Decided (2026-11-10):** the web uses CSS px as the screen unit, with `CM_PER_PX = 2.54/96` (the nominal CSS inch) replacing `CM_PER_DP`. Fields are renamed `errorPx`/`noisePx` in `src/gaze/gazeCalibration.ts`; the math is unchanged. Port the dp-based `FOCUS_JUDGE_POLICY` values the same way.
- Samples flow through `createSampleHub()` (`src/gaze/gazeSample.ts`, up to 10/s from `/try`; the app used 4/s, and a sample is skipped while the previous inference is still running). `CalibrationOverlay` (same timings as the app's overlay except `DOT_TARGET_SAMPLES` 4 → 12, changed 2026-11-11 because 4 samples left too much shake; posture check omitted) the gaze dot, and the focus judge subscribe to it. The gaze dot is display-only smoothing (`GAZE_DOT_POLICY`: 1.5 s median plus a ~1.5 cm deadzone). Calibration coordinates are fullscreen-viewport CSS px.
- **E-book reading scene (`src/pages/ReadingScene.tsx`)** opens from the calibration card once `fittedMap` exists, and covers the fullscreen viewport. Each word is a span whose rect is measured on mount, on `document.fonts.ready`, and on resize. The calibrated gaze goes through `createReadingSmoother`: a median over 1.5 s for x and 2.5 s for y (`READING_POLICY.SMOOTH_*`), plus the gaze dot's 1.5 cm deadzone. y gets the longer window because it shakes more, and the next line is mostly found by the x return sweep, so slow y is fine. A 300 ms EMA was too jumpy. It then snaps to the nearest line (the default, since the ~4.7 cm error is larger than a ~3 cm word; key L switches to nearest word), and the box moves only after `DWELL_MS`. Line mode uses `createLineTracker` instead: the current line holds until gaze y passes the midpoint to a neighbouring line by `LINE_STICK_PX` (~1.6 cm, so gaze has to reach the neighbouring line's centre), then moves to the next line after `LINE_NEXT_DWELL_MS` (0.5 s) or to an earlier or skipped line after `LINE_OTHER_DWELL_MS` (2.5 s), because reading flows downward and the y noise is 2–3 cm. Any forward move (y or sweep) blocks going back up for `SWEEP_NO_BACK_MS` (4 s). These were raised on 2026-11-12 because the box still jumped up and down at 1.2 cm / 1.5 s / 2 s. A jump of more than two lines (e.g. last line back to the first) needs `LINE_FAR_DWELL_MS` (4 s). A return sweep only counts as left → right → left on the current line, after the line has been shown for `SWEEP_MIN_LINE_MS` (1.5 s). Before this, a y move to the next line while gaze was still at the right end left `reachedRight` set, so the following leftward move counted as a second sweep: lines were skipped and pages turned as soon as the last line was reached. Options are one object (`createLineTracker({...})`, defaults in `LINE_TRACKER_DEFAULTS`). `minLineMs` is scaled by the line's width over the longest line, so a short last line still counts. Page end also fires when, on the last line after reaching its right part, gaze moves up to an earlier line for `nextDwellMs`. People look at the top-left after the last line, and that used to send the box back to line 1. While the box is on the last line, a hint (`.ebook-lasthint`) says to look at the top-left. `start(line)` (page open, after alignment, L/Q toggles) and `jump(line)` (bookmark) show that line at once and ignore y for `LINE_START_HOLD_MS` (2.5 s); sweeps still count. Each new page starts on line 0 and resets the smoother, because the 2.5 s y median still pointed at the previous page's last line and pulled the box off the first line. It also advances on a return sweep: once gaze x has passed `SWEEP_RIGHT_FRAC` (65%) of the current line and then comes back left of `SWEEP_LEFT_FRAC` (35%), it moves straight to the next line, and for `SWEEP_NO_BACK_MS` (2 s) it will not go back up. This helps with lines that are hard to tell apart by y. The text area is inflated by `max(TEXT_AREA_MARGIN_PX, cal.errorPx)`, and "글 밖" shows only after `OUTSIDE_MS` (1 s) of continuously being outside. The box never disappears for being outside; it just dims (`.ebook-box.dim`), so it does not blink. Text is 36px with a 120 px line height (≈ 3.2 cm per line). `ebookText.ts` (`EBOOKS`) holds 4 public-domain works of different kinds (오 헨리 「마지막 잎새」 retold, 이솝 「토끼와 거북」, 세네카, 마르쿠스 아우렐리우스). 김구 「나의 소원」 was removed as boring; prefer works with a story. Poems were removed: their short lines made the return sweep fire too fast, so lines were skipped and the page turned early; the foreign ones and the fable are our own Korean translations, never someone else's translation. Each has 3 pages of 90–135 characters, about 4–5 lines (`ebookText.test.ts` checks this; 3-line pages ended too fast). `\n` would be a forced line break (`splitPage` → `<br>`), but no current text uses it. `nextBookIndex` rotates the work on every scene mount and on [다른 글 읽기], remembered in localStorage (try/catch). Flow: alignment, then the pages, then a result card. The page turns when the line tracker reports a return sweep on the last line (`takePageEnd`), at least `PAGE_MIN_MS` (3 s) after the page opened; ← and → also turn pages. `src/reading/readingSession.ts` (`SESSION_POLICY`) takes the focus result (4/s) and records reading time, the focused ratio, distractions and per-line dwell. Reading time pauses on away or eyes closed. A distraction is unfocused or away for more than `DISTRACT_MS` (1 s): the page dims and a bookmark ribbon marks the current line. On refocus the tracker `jump`s back to that line and shows "여기부터 이어 읽어요". The result card shows time, focus %, distraction count, chars per minute, and a per-line dwell bar list that marks the longest line. Do not animate the page with transforms, because word rects are measured right after a page change. Smaller glyphs are fine, but the line height decides whether lines can be told apart. The logic is in `src/reading/readingGaze.ts`. Q shows a 2×2 quadrant view as a spare; it was written fresh because no earlier version existed. G toggles the gaze dot. A focus chip sits top-right. It opens in a two-point alignment step: the user looks at the first word (red frame) and presses Space, then does the same for the last word. From the median of the last 1 s of calibrated gaze at each point, `alignTwoPoint` computes a horizontal shift plus a vertical scale and shift (`READING_POLICY.ALIGN_*`, scale clamped to 0.5–2.5). The vertical scale was added because the bottom lines were hard to tell apart: when looking low, the eyelids cover the eyes and gaze reads too high. R redoes it. This removes posture drift and that vertical squeeze. It cannot fix the model's ~4–5 cm scatter, which is larger than the 3.2 cm line height. The size warning compares the scene's own `getBoundingClientRect()` with `cal.screen`, as `CalibrationOverlay` does. `window.innerWidth` included the setup page's scrollbar and was about 12 px off. It replaced the scroll text box, so skimming cannot be shown on `/try` right now.
- **Focus judging (`src/gaze/focusJudge.ts`)** ports `reference/focusJudge.ts`, which is scroll mode only. The app's newer page mode was left out. Tests port the scroll-mode part of the app's `focusJudge.spec.ts`. The dp values were converted to px of the same physical length (px = dp × 0.6): `STARE_MIN_SPREAD_PX` is 12 and `SKIM_MAX_PX_PER_SEC` is 27. `/try` feeds the judge one sample every 250 ms, as the app did, so sample-count policies keep their meaning. Nothing calls `notifyScroll` now (the scroll box was replaced by the e-book scene).
  - yaw/pitch come from the MediaPipe facial transformation matrix (`src/gaze/headPose.ts`, R = Ry·Rx·Rz). The matrix layout is picked by where the translation sits. The app used ML Kit angles, and judging only compares against a baseline.
  - Eye openness is `1 − eyeBlink`. The app's fixed `EYES_CLOSED_PROB` 0.15 (ML Kit) was replaced with a per-person threshold: closed when both eyeBlink > max(`EYE_BLINK_FLOOR` 0.5, median open-eye eyeBlink + `EYE_BLINK_MARGIN` 0.3). The open-eye values come from calibration (`GazeCalibration.eyeBlinkSamples`), or from the 5 s auto baseline when calibration is skipped. `/try` only judges after calibration, so the auto baseline is not used there (it stays in `FocusJudge`). Measured 2026-11-11: closed eyes read only 0.51–0.63.
- `eye_extractor.py` expects its model at `models/assets/face_landmarker.task`. Here the model sits at `reference/face_landmarker.task`.


# gaze-web: 시선 추적 웹 시연

## 목적
노트북 웹캠으로 시선 모델을 체험하는 전시용 웹. 설계서: "시선 추적 웹 시연 설계서".

## 스택
- Vite + React + TypeScript
- @mediapipe/tasks-vision FaceLandmarker (VIDEO 모드, 얼굴 1개)
- @litertjs/core로 reference/gaze.tflite 실행
- 보정·판정은 reference/의 앱 TypeScript를 옮겨 사용

## 절대 규칙
- git 관련 명령을 직접 실행하지 않는다. 사용자에게 권장한다. 
- main 브랜치에서 직접 작업하거나 push하지 않는다.
- 카메라 영상과 눈 크롭을 서버나 외부로 보내지 않는다. 모든 처리는 브라우저 안에서.
- 눈 크롭은 reference/eye_extractor.py와 숫자 하나까지 같게 만든다 (랜드마크 번호, 224, 0.35, 2.5, 1.8, 64).
- 모델에 넣는 프레임은 거울 반전하지 않는다.
- 패키지 추가는 먼저 물어본다. `git add .` 금지.
- 수집 데이터(눈 크롭, 라벨)는 Git에 올리지 않는다.
- 파일 삭제는 먼저 물어볼 것.
